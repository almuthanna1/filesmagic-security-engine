## 4. Latency and isolation observations

- **Latency** (server-side, Free instance, warm): 16 fixtures min 5,666 ms, median 6,457 ms,
  max 6,996 ms; UI scans 5,764–6,482 ms. Nearly all of this is starting a fresh worker process
  (Python, imports, YARA-X rule compilation) on 0.1 CPU; the earlier Windows development
  machine needed about 0.6 s for the same work. The engine was already awake; Free instances
  add about 50 s or more after 15 minutes idle.
- **Runtime-reported controls** (the worker reports what it applied): `process`,
  `network_namespace`, `rlimits`, `audit_hook` all true on every successful scan, with strict
  mode on.
- **Independently verified by tests** (CI run 40147894857, Linux, Python 3.11, non-root): each
  rlimit is enforced by the kernel; process-group kill; native crash fails closed; inside the
  worker's network namespace an outbound connection fails with `ENETUNREACH`. On Render the
  namespace flag means `unshare(CLONE_NEWUSER|CLONE_NEWNET)` succeeded; a blocked connection
  was **not** demonstrated on Render itself (N1).
- **Not OS containment:** the Python audit hook is an in-process guard; native code is not
  subject to it.
- **Scope of the namespace:** it isolates only the scan worker. The API process keeps normal
  outbound network access.

## 5. Regressions and issues

No regressions. Observations:

1. Login throttling is per Vercel function instance (A4 note); a long random password remains
   the main defence.
2. The Lab's token route answers an over-size request with the generic "Invalid file
   description." (the browser pre-check normally prevents this request).
3. Rule-set hash differs on the Windows development checkout (`34bd65ee595d`) from Render
   (`0be9918509e9`). Verified cause: the Windows working tree has CRLF line endings
   (`core.autocrlf=true`); the committed rule file (LF) hashes to exactly the Render value.
   The rules are identical.
4. Operational: editing a masked value in the Render dashboard requires focusing the field
   first; a first attempt produced "301" instead of "1" and was caught and corrected before
   saving.

## 6. Recommended next improvements

1. Add a worker self-check that runs inside the namespace before the audit hook (no network
   traffic, e.g. the interface list contains only loopback, and a connect to a TEST-NET address
   fails) and report it as a separate isolation field, so N1 can be verified on Render without
   any diagnostic endpoint.
2. Normalise line endings in `ruleset_hash()` (or re-normalise the checkout) so all hosts report
   the same rule-set hash.
3. Return a specific "File is too large" message from the token route.
4. Consider Vercel deployment protection or SSO and a shared throttle store if more than one
   researcher uses the Lab.
5. If latency matters for larger datasets, use a paid instance (more CPU) rather than weakening
   per-scan process isolation.
