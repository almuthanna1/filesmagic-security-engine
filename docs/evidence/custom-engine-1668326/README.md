## Reproduce

```
git checkout 1668326
python -m evaluation.cases --trials 20 --out <dir>/reference
python -m evaluation.cases --trials 20 --engine unified --out <dir>/unified
python -m evaluation.poster --run <dir> --out <figures dir>
```

The fixtures are deterministic on one platform (fixed ZIP timestamps, fixed PDF layout), so a rerun
on this machine reproduces each recorded SHA-256. Across platforms only the PDFs do: the Office
fixtures are DEFLATE-compressed ZIPs, and the compressed bytes depend on Python's zlib build (Linux
CI with Python 3.11 produced different bytes, and hashes, for the same parts; verdicts, rules and
scanner statuses were identical there). Timings differ by machine.

## Files

- `reference/results.json`, `unified/results.json`: per case the verdicts (each scanner and the
  aggregate), the complete findings of the first trial (INFO included), whether all 20 trials gave
  identical verdicts and findings (`deterministic`), scanner statuses, missing isolation controls,
  latency summaries, and every trial's raw wall time and per-scanner durations (`trials`).
- `reference/matrix.md`, `unified/matrix.md`: verdict tables.
- The analysis of this pair (comparison table, pooled latency, figures) is in
  [`docs/poster/figures/`](../../poster/figures/), generated by `evaluation.poster`.

## How to read it

- Ground truth for every fixture is BENIGN: each carries an inert structure, not malware. The
  results show how each engine *classifies indicators*, not how accurately it detects malware.
- Detection results are counted per fixture (n = 16). The 20 trials are repeated scans of the same
  bytes and measure timing variation on one machine; they are not independent samples.
- In the unified run, the per-scanner verdicts of reference scanners are computed after correlation
  removed superseded findings; the reference run is the measurement of the reference scanners.
